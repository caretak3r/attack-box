# AttackBox overview

AttackBox is a defensive honeypot for AI service interfaces. It records how clients interact with a simulated service so defenders can study those interactions.

AttackBox implements OpenAI, vLLM, and Ollama API personas. The responses are synthetic. AttackBox does not run models, execute client instructions, or contact destinations from request payloads.

A separate public gateway answers on public ports like common AI servers. Its answers are also synthetic.

## Functions

| Function | What AttackBox does |
|---|---|
| Simulate | Return protocol-shaped responses without a model backend. Stream synthetic replies over SSE or NDJSON. |
| Observe | Record bounded, redacted observations of client behavior: requests, parsed declarations, probe compliance, and sessions. |
| Collect | Add host runtime evidence from Falco, kernel audit, and privileged snapshots outside the bait container. |
| Validate | Admit records by role and structure. Reject malformed or oversized payloads before queueing. |
| Deliver | Append admitted records to a durable disk queue. Batch and ship logs and metrics to New Relic. Export traces to an OpenTelemetry Collector. |

The supplied Ubuntu deployment uses an nginx proxy on host loopback and enables only the OpenAI persona. Local development does not need Docker, a VPS, or a New Relic key.
